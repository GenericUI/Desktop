# `:desktop:qt` — Linux Qt6 Native Backend (`linuxX64`)

## Overview
`:desktop:qt` is the native Linux Qt6 (`linuxX64`) backend for GenericUI. It uses Kotlin/Native C-Interop (`qt.def`) with a C ABI wrapper over `QApplication`, `QMainWindow`, `QWidget`, `QCursor`, `QPainter`, `QMenuBar`, `QStatusBar`, and `QResource`, and depends on `:common`, `:systemCommon`, `:desktop:common`, `:desktop:nativeCommon`, and `:desktop:linuxCommon`.

---

## Single-`commonMain` Architecture & `QtLauncher`

The GenericUI Gradle plugin (`GenericUiGenerateLaunchersTask`) generates the `linuxX64Main` launcher stub invoking `QtLauncher`:

```kotlin
// Auto-generated by GenericUiGenerateLaunchersTask
fun main(args: Array<String>) {
    QtLauncher.launch(
        args = args,
        title = "My App",
        width = 1280,
        height = 800,
        mainFragmentFactory = { MyMainFragment() }
    )
}
```

When `styles { globalStyleSheet = "styles/main.scss" }` is configured in `build.gradle.kts`, the generated startup code automatically attaches the precompiled `PrecompiledStyleSheet` via `app.addStyleSheet(...)`.

## Native Qt6 Control Rendering (`BootstrapType.NONE` Default), Semantic `BootstrapType` Tinting, & Custom Cursors

1. **`BootstrapType.NONE` Default & Zero Bootstrap CSS Styling**:
   - Native Qt6 applications **never** use Bootstrap CSS styling.
   - When `component.getBootstrap().type == BootstrapType.NONE` (the default) and no inline `ComponentStyle` background/border is set, `:desktop:qt` renders the **authentic Qt6 `QStyle` / `QPalette` system widget** for the active `LIGHT` / `DARK` theme.
2. **Semantic `BootstrapType` Tinting**:
   - When a semantic `BootstrapType` (`DANGER`, `PRIMARY`, `SUCCESS`, `WARNING`, `INFO`, `SECONDARY`, `LIGHT`, `DARK`, `LINK`) is set on `component.getBootstrap().type`, `:desktop:qt` emulates `BootstrapType` by **tinting the native `QWidget`** (`QPalette::Button`, `QPalette::ButtonText`, `QPalette::Highlight` via `DesktopBaseNativeImpl.resolveSemanticBootstrapColor(darkTheme)`), supporting `outline = true/false`.
   - `component.getStyle().setAccentColor(color)` (`accent-color`) sets `QPalette::Highlight` on interactive controls. Unsupported CSS properties and CSS transitions are **silently ignored**.
3. **Strict User CSS Class Isolation**:
   - `addClass`, `removeClass`, `hasClass`, `getClasses()`, and `getClass()` return **only** user-added custom classes (`styleSnapshot.customClasses`).
4. **Custom Cursor Translation (`CssCustomCursor` $\rightarrow$ `QCursor`)**:
   - Translates any PNG `ResourceID`, SVG `ResourceID`/markup, or `ImageBuffer` `CssCustomCursor` into a `QImage` / `QPixmap` and constructs `QCursor(pixmap, hotspotX, hotspotY)` applied via `QWidget::setCursor`.
5. **`IApplication` Theming (`ThemeMode.AUTO`, `DARK`, `LIGHT`)**:
   - Defaults to `ThemeMode.AUTO`, querying `QGuiApplication::styleHints()->colorScheme()` (`Qt::ColorScheme::Dark` vs. `Qt::ColorScheme::Light`) and listening to `colorSchemeChanged`.

## Window Chrome, `TitleCapabilities`, & Single-Placement `TitleBar`

`QtWindowImpl` reports native desktop `TitleCapabilities` (`isTitleBarRequired = true`, `supportsCustomComponents = true`, `canEmbedComponentsInTitleBar = true`, `titleBarRendersAsNavbar = false`). Custom leading, center, and trailing components attached to `TitleBar` are mounted in the `QMainWindow` custom titlebar widget and flagged `mountedInTitleBar = true` so `QtNativeWindowHost` excludes them from the central body widget.

---

## Compiled `QResource` Bundle (`QtResourceResolverImpl`)

During the Gradle build, `GenericUiCompileResourcesTask` generates `genericui_resources.qrc` from `src/commonMain/resources/` and compiles it via Qt's `rcc` tool into a binary `.rcc` resource bundle, resolved at runtime by `QtResourceResolverImpl`.
